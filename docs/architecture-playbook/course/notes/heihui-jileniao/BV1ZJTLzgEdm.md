## 本集解决的问题

本集针对把墙面雕花理解为在单层平面上堆叠方块的问题。课程先用内退墙芯建立雕花空间，再要求细节尺度服从墙面尺度、装饰服从柱梁和承托逻辑，并以竖向开间与横向分层共同组织大墙面。重点不是收集固定花纹，而是建立可复用、可留白、可按比例调整的立面构造流程。

## 字幕摘要

- 单层平墙没有足够进深容纳雕花；先提出边框，再让中间墙芯内退一格。较大的墙面可以继续使用受控的逐层内退，以获得透视层次并把大面切成较小区域（约 0–37 秒及 329–411 秒）。
- 旧式雕花容易出现色调单一、构件精度低和逻辑混乱。小比例墙面应优先使用较小构件；若必须使用整砖或较大楼梯、台阶，则需要相应放大整体比例（约 90–177 秒及 255–327 秒）。
- 混色和功能方块的视觉形态可以丰富墙面，但结构增改不等于无差别增加视觉信息；柱基或装饰若盖住主体柱，就会喧宾夺主（约 133–165 秒及 185–281 秒）。
- 墙根、顶部横梁及其斜撑、托臂或拱形承托是墙面构图的核心；浮在表面的纹样可以减少或省略。课程明确要求适当留白，并让住宅构件遵循可读的支撑逻辑（约 414–468 秒、565–583 秒及 645–685 秒）。
- 中段展示大量部分方块和功能方块的组合，核心方法是按颜色、轮廓和连接形态理解材料，通过有限排列组合试出弧线或支撑，而不是把游戏内名称当作建筑角色（约 498–1,130 秒）。
- 特殊更新抑制、展示实体和编辑工具只用于演示某些构件；它们不是普通便携数据包的必要依赖（约 1,145–1,180 秒）。
- 长横梁应通过竖柱划分为较小开间；过大的开间可再用同色系部分构件细分。上下分层还要用柱、托臂或其他连接构件贯通，避免读成彼此无关的两面墙（约 1,183–1,310 秒）。

## 可执行流程

1. 先确定墙体框架和填充面；建立 `facade_depth_layers`，让墙芯位于边框之后。只有墙面尺度和目标层次需要时才继续内退，不固定层数。
2. 执行 `facade_detail_scale_check`：小墙面使用较小的允许构件；整砖、大面积楼梯或台阶会压过主体时，缩小细节或放大承载它的墙面比例。
3. 在添加纹样前建立 `facade_support_path`：墙根、柱、顶部梁及托臂或拱形连接必须可读。装饰遮住主体柱、悬空或没有角色时删除或降级。
4. 建立 `facade_blank_mask`，允许结构已经成立的区域保持留白；混色、告示牌、活板门或其他细构件只进入限定的细节区域。
5. 用 `vertical_bay_partition` 切分过长墙面，再以与框架兼容的部分构件细分过大的开间；不从字幕臆造固定开间宽度。
6. 用 `horizontal_layer_connection` 检查上下层：横带不能把立面切成互不相关的墙片，柱、框架或承托应跨层保持连续关系。
7. 最终分别检查整体层级和近景连接；所有材料必须来自目标版本与编译器白名单，不引入展示实体、冻结更新或模组依赖。

## 给 Agent 的转化

- `facade_depth_layers`：先由框架和内退墙芯建立进深，再决定是否需要额外层次。
- `facade_detail_scale_check`：细节单元、墙面比例与观察距离共同决定允许的构件粒度。
- `facade_support_path`：墙根、柱、梁、托臂和拱形表达构成优先于表面纹样的承托路径。
- `facade_blank_mask`：留白是明确的立面状态，不是待随机填满的空缺。
- `vertical_bay_partition` / `horizontal_layer_connection`：同时组织竖向开间与横向层级，并检查跨层连续性。
