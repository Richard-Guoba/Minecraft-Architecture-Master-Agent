## 本集解决的问题

本集用创造模式快捷操作说明如何减少重复劳动。其中能迁移给 Agent 的知识是：外部结构完成后明确进入内部施工阶段；从已有建筑采样材料；把带状态的常用组件保存为可复用模板；把照明、挡水等功能方块放入独立的隐藏层。

## 字幕摘要

- 作者在完成建筑外部结构后切换观察方式进入内部，继续制作内饰（约 12–47 秒）。
- 从已建结构直接选取所需方块，比反复搜索材料更适合持续施工（约 47–94 秒）。
- 带文字或其他状态的组件可以连同其数据复制，避免每次重新配置（约 112–167 秒）。
- 常用内饰材料可以整理到便携容器中，形成专门的内饰工具箱并反复调用（约 236–299 秒）。
- 方块 ID 和状态信息用于精确指令式编辑；屏障和光源方块承担挡水、照明等不可见功能（约 326–447 秒）。
- 调试棒改变方块朝向、连接和其他状态；隐形展示框通过薄层叠加形成像素级纹样，但存在遮挡与厚度限制（约 448–629 秒）。

## 可执行流程

1. 外部壳体通过结构检查后，创建独立的 `interior_pass`，不要把内饰细节混进体块阶段。
2. 从已批准的建筑区域采样材料，形成按用途分类的 `semantic_material_kit`，例如外墙、屋顶、内饰和景观。
3. 对告示牌、朝向构件或其他带状态方块使用 `stateful_component_template`，同时保存方块 ID、状态和允许的数据字段。
4. 将光源、屏障和其他不可见辅助结构放入 `utility_layer`；它们不得替代可见的承托或材料逻辑。
5. 编译前检查可见层与 utility 层的碰撞、遮挡和版本兼容性。

## 给 Agent 的转化

- `construction_stage: exterior_shell → interior_pass`：明确从外壳转入内部施工。
- `semantic_material_kit`：从已有方案中按建筑角色组织材料，而不是每次重新检索。
- `stateful_component_template`：可复用组件同时携带方块状态；方向和连接不能丢失。
- `utility_layer`：照明、挡水或定位等隐藏功能与可见建筑层分开编译和检查。
- `layered_micro_detail`：薄层装饰必须记录占用深度和遮挡顺序，不能假设所有图案可以共面叠加。
