## 本集解决的问题

本集说明如何在基础单体上做“结构的加法”：先改变体块比例，再把不同体块相互穿插，而不是把相同盒子松散并排；随后用次级房间、门厅、塔楼、老虎窗、棚屋或景观构件切分大墙面。给 Agent 的核心不是无限加装饰，而是用少量有主次、能连接、看起来受支撑的体块提高整体层次。

## 字幕摘要

- 单一盒体即使加屋顶仍容易显得重复；阳台、门厅等附属结构能让基础单体更生动，并减少依赖雕花的细化工作（约 21–133 秒）。
- 拼接前先把基础方体拉高或压扁；高、横等不同方向的体块组合，比重复相同方体更容易形成层次（约 135–193 秒）。
- 相同体块仅并列会显得松散；让体块重叠、嵌套并共享一部分空间，可加强连接，也便于安排楼梯和内部构件（约 229–303 秒）。
- 组合时应让关键观察角度能读到多个体块，并用较宽、较低的横向体块稳定高体块；所有体块排成一线会在其他角度失去效果（约 303–385 秒）。
- 附属体块可把大墙面切成较小区域，局部精细化后允许其余区域留白，从而控制施工量（约 419–657 秒）。
- 体块形状不必全是方盒；圆柱、圆锥或曲面附属体可以提高组合变化，但仍要服从建筑类型和整体结构（约 657–730 秒）。
- 中世纪或高体量方案应让底部和周边体块看起来能承托上部；悬挑、连廊等若缺少支撑，应补充明确支撑（约 526–612 秒及 938–950 秒）。
- 附属构件应放在合适的位置并承担具体角色，例如门厅、塔楼、老虎窗、棚屋、柴堆、灯架或树木；难点是选择与布置，而不是无差别堆满（约 750–840 秒及 846–1025 秒）。

## 可执行流程

1. 从一个满足用途的 `primary_mass` 开始，生成少量长、宽、高不同的 `secondary_mass`；禁止用多个完全相同的盒体直接并排代替构图。
2. 为每个次级体块指定 `attachment_role`，例如 entrance、stair、tower、roof_break、service 或 landscape；没有角色的附加体块应删除。
3. 通过 `mass_overlap` 让相邻体块发生可解释的嵌套或共享连接面，并运行内部通行、碰撞和接缝检查。
4. 在 `primary_view` 及至少一个转角视图检查 `mass_visibility`；主视图应能辨认主次体块，转角视图不得退化成一条平直队列。
5. 对高体块执行 `visual_support_check`：底部可通过加宽、退台或相邻低体块形成稳定承托；悬挑和连廊必须连接到可见支撑路径。
6. 对过大的连续墙面使用 `facade_partition_volume` 切分，再把细节预算集中到入口、转角和连接处；保留有意图的留白。
7. 最后添加少量 `subordinate_component`，并检查其尺度、颜色、支撑和遮挡关系；不要用附属构件掩盖松散的主体体块。

## 给 Agent 的转化

- `mass_ratio_variation`：次级体块相对主块在长、宽或高上产生明确差异。
- `mass_overlap`：体块通过嵌套或共享连接面形成一个建筑，而不是相邻的多个孤立盒子。
- `attachment_role`：每个新增体块必须解释其入口、交通、屋顶转折、服务或景观用途。
- `multi-view mass_visibility`：从主视图和转角视图检查体块层次，避免单面堆叠。
- `visual_support_check`：高体块、悬挑与连廊需要可读的底部宽度、退台或支撑路径。
- `facade_partition_volume`：用次级体块切分大墙面，并把细节预算集中到关键小区域。
- `subordinate_component`：门厅、塔楼、老虎窗、棚屋、灯架和植物等只作为从属构件，不得抢过主体。
