## 本集解决的问题

本集解释为什么小房子不能仅靠等比放大变成可信的大建筑：体量增大后需要可读的柱、梁、楼板和屋顶承托关系，并按建筑尺度重复成网格。支撑不能无限堆叠，因为过密的柱会挤压室内空间；柱梁框架需要表达左右稳定、拱形构图暗示水平推力或斜撑比例不合适时，应改变支撑方案、建筑尺度或构件表达。

## 字幕摘要

- 小房子简单等比放大会失去可信的支撑直觉；材料角色和整体形状共同影响建筑看起来能否站立，但示例只讨论视觉与写实逻辑（约 0–158 秒）。
- 基础竖向支撑由柱表达，柱可分为柱头、柱身和柱脚；二层楼板与屋顶还需要横梁承托（约 160–238 秒）。
- 大建筑应由多个柱梁开间组成，而不是放大一个无分段盒体；屋面应落在可读的梁上，不能像悬空一样结束（约 239–305 秒）。
- 柱并非越多越好：过密柱网会挤压内部空间；通过长梁、抬梁或其他跨越策略减少中部柱时，复杂方案需要足够尺度才能表达（约 305–430 秒）。
- 除竖向承托外，还可用斜撑、加厚侧部、扶壁或地形连接表达对侧向推力的抵抗；拱形构图尤其需要考虑两侧承托（约 431–599 秒）。
- 标准楼梯斜撑只有固定坡度且视觉厚度较大，较适合更大的房屋；整块阶梯线或小型构件可表达不同坡度和厚度（约 605–748 秒）。
- 小构件与同色材料可以细化斜撑，但展示实体数量过多会造成性能问题；模组强制放置和实体技巧不应成为可移植数据包的依赖（约 749–966 秒）。

## 可执行流程

1. 在体块放大前执行 `support_system_scale_check`：若宽、高或跨距增加，先把主体划分为可重复的 `structural_bay`，不要整体等比拉伸单一外壳。
2. 为每个开间建立 `column_beam_grid`：竖向柱连接到地基或下层支撑，横梁连接相邻柱并承托上层楼板或屋顶。
3. 执行 `roof_bearing_alignment`：屋面边缘、坡脚或内部屋架必须落到梁、墙或柱的可读路径上；悬空终止则移动或补充承托构件。
4. 执行 `support_density_tradeoff`：检查柱网是否阻断入口、主要通行或目标内部空间；若过密，选择更长横梁、抬梁或适合当前尺度的跨越构图，而不是无条件删柱。
5. 柱梁框架需要表达左右稳定时，用连接柱梁节点的斜撑；拱形构图暗示水平推力时，从侧部加厚、扶壁或地形连接中选择与风格相符的 `lateral_support_strategy`。
6. 用 `diagonal_support_profile` 指定斜撑的坡度、厚度、材料角色和连接端；构件两端应接到已有柱梁或墙体，不得成为漂浮装饰线。
7. 按尺度选择方块形态：大尺度可用楼梯或整块阶梯线，小尺度可用允许的薄构件细化；最终仍由白名单相对坐标方块编译，不引入 Axiom、冻结更新或展示实体依赖。

## 给 Agent 的转化

- `support_system_scale_check`：体量增大时增加可读开间和承托层级，而不是只放大外壳。
- `structural_bay` / `column_beam_grid`：用重复柱梁单元组织大建筑，并维持从屋顶、楼板到地基的连续路径。
- `roof_bearing_alignment`：屋面必须落在梁、墙或柱上，不允许无解释悬空。
- `support_density_tradeoff`：在支撑可读性与入口、通行、内部空间之间做取舍。
- `lateral_support_strategy`：用斜撑表达柱梁框架的左右稳定；对暗示水平推力的拱形构图使用侧部加厚、扶壁或地形连接。
- `diagonal_support_profile`：斜撑坡度与厚度服从建筑尺度，并连接到真实结构节点。
