# 建筑秘籍与秘籍驱动建造计划设计

日期：2026-08-24

状态：等待书面设计审阅

范围：知识提炼、可执行秘籍、秘籍驱动设计层闭环及分阶段扩展

## 1. 目的

本计划解决两个必须同步完成的问题：

1. 如何从数量庞大、教学思路可能不同的视频、地图和案例中，建立忠实、可追溯、不会混淆学派的 Minecraft 建筑秘籍；
2. 如何让秘籍不止是一篇教程，而能真实影响建筑 Agent 的设计决策，并通过预览、评价和定向返工逐步提高建筑质量。

计划不要求项目所有者先成为建筑大师。课程作者提供教学体系，自动化流程负责转写、索引、归纳和格式化，项目所有者只在高影响规则、冲突和少量 A/B 建筑选择上担任审美总监。

## 2. 当前项目诊断

当前 `construction_method_v1` 已经具备可靠的语义输入、确定性体素化、房间切分、寻路、装饰、QA 和数据包导出能力，但仍有三项关键缺口：

- 设计自由度主要由有限的本地变体、默认值和固定专项算法决定；
- 自动提炼的模板法则有来源案例，却没有可信的作者教学体系或充分的视觉因果解释；
- 当前评分主要验证合法、可住、模块齐全和复杂度，二维预览无法证明外观漂亮，也没有设计层级的视觉返工闭环。

因此新计划不替换现有几何与 QA 地基，而是在其上新增可追溯的设计知识、分层设计程序和视觉反馈。

## 3. 已批准的核心决策

### 3.1 唯一主学派

第一版只把黑辉极乐鸟的《极乐鸟的建筑课堂》设为 `primary_school`。主学派内部允许存在更新、例外和未解决冲突，但不允许其他作者通过多数投票或无标记融合改写其规则。

后续来源使用单独的 `school_id`。它们只能提供：

- `contrast`：不同做法的并列对照；
- `boundary`：主学派规则的适用边界；
- `counterexample`：用于压力测试的反例；
- `product_choice`：产品层明确选择或组合的记录。

### 3.2 双闭环垂直切片

采用“知识闭环”和“建造闭环”交替推进，而不是先处理完 50 集再接入生成器。

```text
知识闭环
课程媒体
-> 证据段和课次笔记
-> 作者观点、画面事实和团队推论
-> 条件化规则卡
-> 人类可读秘籍

建造闭环
用户提示
-> 检索适用规则
-> 分设计层生成候选
-> 确定性编译为 Minecraft 几何
-> 固定多视角预览
-> 规则审查、视觉审查和人工偏好
-> 只返工受影响的设计层
```

### 3.3 最小完成标准

第一轮必须同时达到以下结果：

- 6 集课程产生可追溯的秘籍 v0.1；
- 秘籍指导生成一栋中世纪民居的至少三个候选；
- 候选输出固定多视角预览；
- 至少完成一次针对具体设计层的返工，而不是整栋随机重跑；
- 与当前生成器完成盲选比较；
- 无论视觉是否已经胜过基线，都留下可解释的成功、失败和下一轮修正证据。

最小闭环的目标是验证方法，不把一次小样本胜负包装成生产质量结论。

## 4. 方案比较

### 4.1 全课优先

先处理全部 50 集，完成完整讲义后再考虑 Agent 接入。优点是课程结构连续；缺点是很晚才能发现规则格式是否可执行、视觉反馈是否有效，以及课程内容能否映射到当前生成器。

### 4.2 工程框架优先

先实现规则合同、检索、checkpoint 和视觉评价，再填入课程内容。优点是工程边界整齐；缺点是知识结构会根据开发者想象而非真实教学设计，容易重复当前“字段很多、建筑经验很少”的问题。

### 4.3 双闭环垂直切片（采用）

先用一集验证媒体处理，再用 6 集建立从证据到建筑返工的完整路径，随后按原课程章节扩展。它能以最小内容暴露知识、工程和视觉三类问题，并避免形成无法被 Agent 使用的大型静态教材。

## 5. 来源、版权与本地边界

### 5.1 提交边界

Git 中只提交原创、转换后的结构化知识：

- 课程和课次元数据；
- 来源链接和时间戳；
- 简短原创转述与画面描述；
- 规则卡、冲突记录、讲义和评价设计；
- 由本项目生成的测试建筑和评价结果。

以下内容只允许位于 `.local/architecture-playbook/`，不得提交、发布或当作已获训练授权的数据：

- 下载或缓存的源视频、音频；
- 完整或接近完整的字幕、自动转写；
- 大量源视频截图；
- 尚未完成权利审查的衍生数据集；
- 私有人工评审记录。

公开视频可访问、平台允许缓存、本地分析、模型训练和对外发布是不同状态，必须分别记录，不得互相推定。

### 5.2 来源变化

每集记录稳定 BV 号、规范 URL、作者、标题、时长、抓取时间、公开状态、公开权利提示和内容指纹。视频删除、改名、改时长或暂时不可访问时，保留旧记录并标记状态，不用相邻视频或其他作者内容自动替代。

## 7. 知识模型

### 7.1 四类陈述

所有课次笔记必须区分：

- `fact`：作者实际说了什么、做了什么，或画面前后发生了什么；
- `author_claim`：作者明确推荐、反对或限定的观点；
- `inference`：本项目从一次或多次证据中推导的条件化规则；
- `contrast`：其他学派或外部资料的不同方法。

画面可见但作者没有说出的内容只能记为 `observed_demo` 类型的事实，不能伪装成作者观点。听不清、看不清或推理链不足时使用 `unresolved`，禁止模型补全。

### 7.2 核心合同

#### `CourseManifest`

记录课程、作者、主学派、课次顺序、来源状态、时长、内容指纹、公开权利提示和处理状态。

#### `EvidenceNote`

记录课次、时间范围、陈述类型、原创转述、画面描述、支持的规则候选、置信度和审核状态。

#### `PlaybookRule`

至少包含：

```text
rule_id / rule_version / primary_school
source_episode / time_range / evidence_ids
claim_type / design_layer / intent
applicability / prerequisites / exclusions
action / parameters / implementation_hints
positive_signs / failure_modes / repairs
author_reason / confidence / review_status
conflict_ids / supersedes
```

未知参数保持 `unknown`。不能因为生成器需要数字就虚构比例。

#### `RuleConflict`

并列保存冲突规则、各自证据、场景条件和处理结果。只有作者明确更新或撤回旧观点时才使用 `superseded`；其他情况标记为条件差异或未解决冲突。

#### `PreferenceRecord`

记录候选对、随机左右顺序、胜者或平局、信心、原因标签、截图版本、规则版本和自由文本。它取代单一的绝对审美分。

### 7.3 规则成熟度

规则按证据逐步升级：

1. `observed`：单次作者陈述或演示；
2. `candidate`：已形成条件、动作和可观察结果；
3. `reviewed`：忠实性和适用边界已审；
4. `executable`：能映射到设计程序或检查器；
5. `validated`：在未参与规则编制的测试提示或案例上得到支持；
6. `limited`：只适用于明确范围；
7. `deprecated`：保留谱系但不再默认检索。

出现次数不会自动把规则升级为普遍真理。

## 8. 课程处理流程

### 8.1 单集处理

```text
课次元数据
-> 音频转写草稿（带时间戳）
-> 语义段落划分
-> 教学转折和前后对比关键帧定位
-> fact / author_claim / inference 分层笔记
-> 规则与反例候选
-> 忠实性审查
-> 批内作者规则归纳
```

无官方字幕时，自动语音识别只能产生 `draft_transcript`。方块名、材料名、数字、比例、否定句和“但是/除非/不要”等边界词必须重点复核。关键帧按教学事件提取，不按固定时间间隔制造大量无意义图片。

### 8.2 第一技术探针

第一集固定为 `1.2 结构主次`，BV 号 `BV1HhEuzZEyZ`。探针只回答媒体取得、转写、时间码、关键帧、术语纠错和证据包是否可行，不编写生产规则，也不改变生成器。

探针通过条件：

- 能稳定定位至少一个完整教学段落；
- 转写和画面能够共同支持忠实的原创笔记；
- 不确定内容可被结构化标记；
- 原始媒体和转写没有越过本地边界；
- 同一输入和配置可重建相同证据索引。

## 9. 人类可读秘籍

秘籍 v0.1 包含：

1. 作者的建筑方法和术语；
2. 体块与结构入门；
3. 结构主次；
4. 屋顶如何服务整体轮廓；
5. 墙面、开口和深度层次；
6. 中世纪民居的条件化组合；
7. 从完整范例复盘设计顺序；
8. 常见失败、反例和修复；
9. Agent 使用流程与规则索引；
10. 未覆盖、冲突和待验证内容。

每个核心结论都反向引用规则版本和课次时间码。讲义允许解释和重组，但不得改变规则卡中的作者归属、条件和证据强度。

## 10. 秘籍驱动建造架构

### 10.1 设计权分层

LLM 和秘籍负责：

- 选择适用规则和说明适用原因；
- 决定体块主次、相对附着、设计意图和可变轴；
- 决定结构表达、屋顶轮廓、立面节奏和材料角色；
- 产生有限、结构化、可回放的设计层 patch；
- 根据视觉证据提出定向返工。

本地确定性系统继续负责：

- 绝对坐标、尺寸夹紧、方块合法性和碰撞；
- CSG/BSP/A*、门洞、楼梯、可达性和净空；
- 体素化、命令优化、数据包导出和硬 QA；
- 超出规则能力时的安全降级。

LLM 不直接输出整个建筑的逐块坐标。

### 10.2 设计层 DAG

完整设计层集合为：

```text
brief
-> massing
-> space
-> structure
-> roof
-> facade
-> materials
-> interior
-> scene
```

实际依赖不是简单直线。例如 `scene` 依赖 `brief/massing/materials`，`interior` 依赖 `space/materials`。合同以显式依赖哈希表达，而不是依赖隐含执行顺序。

六集 v0.1 只启用：

```text
brief -> massing -> structure -> roof -> facade
```

`space/materials/interior/scene` 保持当前生成器行为，并明确标记 `playbook_coverage: not-covered`。后续课程章节逐步接管，禁止假装 v0.1 已经覆盖整个住宅设计。

### 10.3 `DesignLayerCheckpoint`

每个设计层保存：

```text
build_id / layer / revision / status
upstream_accepted_hashes
selected_rule_ids / rejected_rule_ids
design_intent / recipe_fragment / field_patches
compiled_artifacts / preview_manifest
hard_qa / design_review / visual_review
invalidates_downstream / replay_origin
```

状态为 `draft`、`reviewing`、`accepted`、`rework_required` 或 `superseded`。只有已接受的上游版本能成为下游输入。

修改体块会使所有相关下游失效；修改屋顶不应重做体块；修改材料不得静默改变房间布局；修改场景不得改变主体结构。返工失败时回到最近一条完整的 accepted chain，保留失败证据。

### 10.4 三个接入等级

#### 等级 A：影子指导

秘籍只审查现有输出并说明：采用了什么规则、违反了什么规则、证据是什么、建议修改哪一层。生成器行为保持不变。

#### 等级 B：候选选择

秘籍参与生成多个设计候选并淘汰明显违反规则的方案，但最终几何仍使用现有编译路径。

#### 等级 C：设计层控制与返工

秘籍驱动结构化设计程序，checkpoint 接受视觉反馈并只重放受影响层及其下游。只有达到等级 A、B 的门槛后才能开启等级 C。

## 11. 视觉评价与人工偏好

### 11.1 硬 QA 与审美分离

现有工程 QA 继续判断命令、密闭、房间、连通、楼梯、材料合法性和导出。视觉评价只在硬 QA 通过后运行，不把合法性、模块数量或方块种类包装成审美分。

### 11.2 固定多视角

每个候选至少输出：

- 正立面；
- 侧立面；
- 东南和西南两个四分之三外观；
- 屋顶鸟瞰；
- 入口人眼视角；
- 可选夜景。

相机位置根据建筑 bounds 确定，固定 FOV、时间、天气、材质配置和 UI 状态。不能为了某个候选临时挑选最好看的角度。

### 11.3 视觉输出

视觉审查按体块主次、结构逻辑、轮廓、屋顶、立面节奏、材料、细节、场景和风格一致性输出 `strong/usable/weak/fail/unknown`，每条结论引用截图 ID 和可观察证据。看不清时只能给 `unknown`。

人工评价使用随机左右顺序的 A/B/平局选择，并记录原因标签与信心。AI 负责筛选和解释，不担当最终审美真值。当前总分继续作为工程诊断，不参与视觉盲评。

## 12. 分阶段路线与验收门槛

### P0：规划与安全边界

产物：设计规范、计划入口、本地忽略边界。

验收：没有移动现有代码或数据；`.local/architecture-playbook/` 被整体忽略；当前生成器行为不变。

### P1：课程 manifest 与单集探针

产物：50 集来源账本、单集媒体处理报告、证据合同草案。

验收：50 集有稳定身份；单集证据包可重建；不确定内容和权利状态被诚实表达。

### P2：六集证据包

产物：6 份课次笔记、证据索引、规则和反例候选、冲突与未知清单。

验收：所有候选规则可回链到证据；没有跨学派内容；涉及形体的结论同时有语言或画面依据；无证据内容不入规则库。

### P3：秘籍 v0.1

产物：已审规则卡、人类讲义、术语表、覆盖矩阵。

验收：规则具有条件、动作、可观察结果、失败和修复；讲义核心结论可回链；未覆盖层明确为未覆盖。

### P4：影子指导

产物：当前生成器的规则匹配、违规、缺证和返工建议报告。

验收：关闭 playbook 时旧输出不变；每条建议定位单一设计层和规则证据；秘籍不能静默修改 voxel grid。

### P5：最小可执行设计层

产物：至少三个中世纪民居候选、`brief/massing/structure/roof/facade` checkpoint、确定性重放记录。

验收：每个秘籍驱动决策有规则 ID 或明确标记为现有 heuristic；所有候选通过硬 QA；至少一次返工只重放目标层及其下游；失败可回到最近 accepted chain。

### P6：多视角与盲选

产物：固定视角 manifest、分层视觉报告、人工 A/B 记录、与当前基线的比较。

验收：同一相机协议可复现；视觉结论引用画面；把三个秘籍候选和一个当前基线匿名化，对四个方案完成全部 6 组两两盲选；结果无论胜负都生成明确的下一轮动作。

P6 只证明最小闭环成立。若秘籍候选未胜过基线，先修正规则映射、设计层表达或视觉评价，不通过扩大课程数量掩盖失败。

### P7：按章节扩展其余 44 集

按原作者课程结构逐章推进：

1. 基础工具、方块、模块化和配色；
2. 完整结构；
3. 完整屋顶；
4. 完整墙面；
5. 造景和地形；
6. 内饰；
7. 进阶建筑；
8. 风格和专项案例。

每章重复“证据包、作者内归纳、规则审查、影子测试、可执行接入、视觉回归”。新增章节不得降低六集 golden flow；失败时知识库继续 pin 到最近通过版本。

### P8：完整单学派秘籍 v1

产物：50 集索引、完整作者规则库、讲义、冲突谱系、正反例库、视觉回归集和操作报告。

验收：锁定课次和提示集在版本冻结后只运行一次；每个核心结论可追溯；每个启用设计层至少有未参与规则编制的验证案例。

### P9：其他学派和案例来源

每个新作者先建立独立的 6 集探针和学派合同。可复用证据格式、checkpoint、相机和偏好工具，但不能复用中世纪特有的必须项和禁用项。跨学派融合只能由显式产品策略产生带来源的组合规则。

## 13. 错误处理与回退

- 视频不可访问：课次标 `source-unavailable`，不自动替换。
- 无字幕或转写不可靠：保留草稿和 `unresolved`，规则不升级。
- 作者前后冲突：创建 `RuleConflict`，不平均、不覆盖。
- 规则无法映射当前几何：保留为 advisory，不伪装成 executable。
- 视觉预览失败：停止视觉采用，保留硬 QA 和影子报告。
- 视觉 AI 与人工分歧：降低自动化权限，扩大人工复核，不修改真值标签迎合模型。
- checkpoint 重放失败：回到最近 accepted chain，保留失败版本和原因。
- playbook 运行异常：`playbook=off` 回到原 `construction_method_v1`。
- 课程扩展退化：pin 已通过的知识库和规则版本，新增内容不进入默认检索。

## 14. 测试策略

### 14.1 知识合同测试

- 严格字段和版本验证；
- BV 号、课次和证据引用完整；
- 未知参数不能被默认数字覆盖；
- 规则状态转换合法；
- 冲突和 supersede 谱系可追踪；
- 不同 `school_id` 默认互相隔离；
- 无来源规则不能升级为 reviewed/executable。

### 14.2 课程处理测试

- manifest 生成确定；
- 同一源、配置和处理器版本得到相同段落/证据索引；
- 不可访问、改时长和无字幕状态有稳定报告；
- 原始媒体路径永远落在 `.local/architecture-playbook/`；
- 报告和日志不泄露完整转写或敏感本地路径。

### 14.3 runtime 测试

- playbook 关闭时现有 mock 输出不变；
- 检索只返回适用学派、层级和版本的规则；
- 决策追踪能回链到规则和证据；
- checkpoint 哈希、revision 和失效传播正确；
- 单层返工只重放目标及下游；
- 回退到最近 accepted chain 可复现；
- 硬 QA 始终优先于视觉偏好。

### 14.4 视觉与偏好测试

- 固定相机 manifest 稳定；
- 刻意构造的平顶替换、主次失衡、随机墙饰和现代材料污染能被标记；
- 视觉审查缺图时输出 unknown 而非猜测；
- A/B 左右随机化并检查位置偏差；
- AI 和人工看不到现有总分，避免分数锚定；
- 新版本在冻结的正反例和提示集上不发生关键层级退化。

## 15. 人工参与预算

项目所有者不承担逐集转写和完整观看任务。第一轮只需要：

1. 审核一小组高影响规则及其原创转述；
2. 对未知、冲突或可能误解作者的内容做选择；
3. 完成三个最小候选和一个基线之间的 6 组两两 A/B 判断；
4. 批准是否从六集扩到下一课程章节。

如果高影响规则仍需要项目所有者重新观看大量视频，说明证据包没有降低审阅成本，该阶段不能扩张。

## 16. 非目标

第一轮不包括：

- 训练端到端整屋神经生成模型；
- 收集数百栋住宅；
- 同时建立多个作者学派；
- 处理完整室内、造景、城堡或城市规划；
- 让 LLM 输出全屋逐块坐标；
- 用单一审美总分替代视觉证据和人工偏好；
- 发布源视频、完整字幕、截图集或未经单独审查的衍生数据；
- 重写现有生产生成器或删除当前模板/训练路径。

## 17. 下一道门

本设计通过用户审阅后，下一步是编写详细实施计划。实施计划必须：

- 把 P0–P6 拆成可独立验证的小任务；
- 对每项代码改动先写失败测试；
- 指定准确文件、合同、命令和预期结果；
- 先完成课程 manifest 和单集探针，再允许处理六集；
- 先完成影子指导，再允许秘籍获得生成权限；
- 先验证固定多视角和定向返工，再允许扩展其余 44 集。

P7–P9 只保留为后续子项目，不进入第一个实施计划，防止计划再次膨胀成无法完成的研究工程。
